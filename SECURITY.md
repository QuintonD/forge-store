# Forge Security Policy & Threat Model

> Scope: the Forge storefront (`forge.example`), its demo runtime, and the submission pipeline.
> Contact: **security@forge.example** · PGP on public keyserver · 24h triage SLA.
> Bounties: **$500–$5,000** for sandbox escapes or provenance forgery (see [Rewards](#rewards)).

## 1. Product-specific threat model

Forge distributes *machine-generated* software. The attacker model therefore includes a novel
class: **the model itself as an unwitting insider** (prompt-injected code, hallucinated
dependencies, typosquatted package names) and **submitters gaming automated review**.

| # | Threat | Vector | Primary control | Status |
|---|--------|--------|-----------------|--------|
| T1 | Malicious demo escapes sandbox | JS exfil via `fetch`, storage probing | iframe `sandbox="allow-scripts"` (opaque origin, no same-origin, no cookies, no forms, no popups); CSP `connect-src 'self'` | ✅ shipped |
| T2 | XSS in storefront | Injected copy through app metadata | React escaping everywhere; zero `dangerouslySetInnerHTML` in codebase; CI grep gate | ✅ shipped |
| T3 | Dependency compromise | Typosquat / poisoned transitive dep | Lockfile-strict `npm ci`; Dependabot weekly; `npm audit` gate in CI (critical blocks) | ✅ shipped |
| T4 | Provenance forgery | Fake "generated by" claims, replayed builds | Reproducible-build verification (byte-for-byte re-run) + ed25519-signed in-toto-style attestation per release | 🟡 **demo artifacts signed & verified today** (`npm run verify`); full-app attestation rollout Q1 |
| T5 | Rating/review manipulation | Review rings, self-review farms | Reviews bound to verified installs; launch-cohort integrity screening; published takedown log | 🟡 enforcement design final (current reviews are seeded demo content) |
| T6 | Clickjacking of store actions | Framing storefront | `X-Frame-Options: DENY` + CSP `frame-ancestors 'none'` | ✅ shipped |
| T7 | Supply-chain of Forge itself | Attack on our build/CD | Trunk-based dev with protected `main`; required validation agent + typecheck + budget gates; immutable hashed assets; instant rollback | ✅ shipped |
| T8 | Model-generated secret leakage | Keys hallucinated into submissions | Secret scanning (entropy + provider regexes) as blocking static-analysis stage | 🟡 rollout Q1 |

## 2. Controls implemented in this repository

| Control | Where |
|---|---|
| Validation agent (90 executable checks: catalog integrity, demo safety, routes, a11y cues, budgets, security surface) | [`scripts/validate.mjs`](../scripts/validate.mjs) — runs `prebuild`, `postbuild`, and in CI |
| Demo isolation | `sandbox="allow-scripts allow-pointer-lock"` on demo iframes (`src/components/DemoModal.tsx`) |
| Static security headers (CSP, HSTS, nosniff, COOP, permissions lockout) | [`public/_headers`](public/_headers), [`vercel.json`](vercel.json) |
| Automated adversarial LLM code review on PRs | [.github/workflows/code-review.yml](.github/workflows/code-review.yml) (advisory) |
| Dependency hygiene | `.github/dependabot.yml` (weekly, grouped minor/patch) + audit step |
| No-secrets policy | CI grep for markers; secret scanning stage in submission pipeline |

### CSP status (hardened)

Demos ship as static files under `/demos/*.html` with their own restrictive CSP
(`default-src 'none'` + inline scripts allowed only there, plus a `sandbox` directive).
The top-level storefront CSP now enforces **`script-src 'self'` with no `'unsafe-inline'`** —
arbitrary inline script is dead in the main document. The strong runtime boundary remains
the opaque-origin sandbox on demo iframes. Remaining hardening: per-document SHA-256 hashes
in place of `'unsafe-inline'` inside demo documents (low value behind the sandbox; tracked).

## 3. Incident response

| Phase | Target | Actions |
|---|---|---|
| Detect | < 15 min from signal | Status-page alerts, CDN anomaly alerts, user reports queue |
| Contain | < 1 h | Unlist artifact (store-level kill switch), rotate any implicated keys, snapshot evidence |
| Notify | < 72 h | Users affected via banner + email; regulators where GDPR/EU-AI-Act obligations apply |
| Fix | severity-based | critical < 24 h, high < 72 h, else next train |
| Learn | < 5 working days | Blameless postmortem published to `/postmortems` |

Severity ladder: **S1** sandbox escape or provenance forgery (bounty eligible) · **S2** data
exposure, auth bypass · **S3** defacement/spoofed listings · **S4** availability only.

## 4. Rewards

| Finding class | Range |
|---|---|
| Demo sandbox escape (script execution to origin/data access) | $2,000–$5,000 |
| Provenance forgery / non-reproducible accepted build | $2,000–$5,000 |
| Storefront XSS / injection | $500–$1,500 |
| Header/transport misconfig | $200–$500 |

Rules: no testing against other users, no automated scanning of the review infrastructure,
report privately, safe harbor for good-faith research.
